Bleep Live Link: interface mockups

Two surfaces: the Max for Live device in Ableton Live, and the Live Params node on the board. These are design sketches, not screenshots. The device's logic is in live-link.js and tested outside Max; everything that shows a Live parameter's name or items on the board needs the device to send that back, which is not built.

1. In Live: the Bleep Live Link device Max for Live

One device = one channel = four rows. Each row has a Map button that doubles as its status line, the mapped parameter's controls, and a × to let go of it. A row works out by itself whether it was mapped to a continuous parameter (a dial) or a discrete one (a switch or a menu).

If live.map cannot map what was clicked it answers id 0, and the row says so. Nothing is refused for being a switch or a menu: the row treats a discrete parameter as a menu.

2. On the board: the Live Params node Beautiful Bleep

A node has four inputs and a Channel setting. Add one node per device, up to eight. Each jack gets the Live parameter's name once the device sends it; until then it reads "Ch 1 · Row 2". Beside each jack sits the widget for that row's type.

All four jacks are control jacks. The board only refuses cables to or from notes and patch bays, so a gate or trigger cable fits any row; what the value means depends on what the row is mapped to (a dial, a switch or a menu).
