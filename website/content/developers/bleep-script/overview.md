# Bleep Script

**Bleep Script** is a way to write board modules, message routing and whole patches in code, using **AssemblyScript** and **TypeScript**. A *Code* module on the board has an editor and a Compile button; its declared parameters, probes and buttons become real knobs, jacks and meters.

Status: early. The compiler works in the browser and the Code node is in the web board; most of the design is still a concept.

## What it covers

| Job | Example |
|---|---|
| Custom message routing | Notes, gates, triggers and CC between modules |
| Custom scripting | Control logic, sequencing, generative rules |
| Custom modules | DSP written by you |
| Complex patches | A cell with 100 oscillators generated by a loop |

## How it works

- **Three layers by when code runs.** Patch building runs once, at build time, in TypeScript in a sandbox. Control code runs per event and per 32-sample block. Audio code runs per sample. You pick the rate by which method you write.
- **A restricted subset in real time.** The compiler rejects what the audio thread must not do: unbounded loops, recursion, allocation and extra imports.
- **The usual module format.** The output is one `.wasm` file that follows the [module ABI](../modules/module-abi.md) and runs in the same sandbox as every other module, in the plugins, the app and the browser.
- **Share source, not binaries.** A shared script is text; each viewer's app compiles it locally.
